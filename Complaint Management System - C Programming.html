Introduction

This is a network based application written in C. Users send campus maintenance complaints to a central server. Every complaint gets a unique ID and is saved in a file, and staff can change the status later. The user can check the status using the ID.

Problem: complaints come through paper notes or messages, so they get missed or delayed, nobody knows if it is pending or resolved, and records are scattered.

Objectives:

  • keep all complaints in one place on the server
  • let many clients connect at the same time
  • unique ID for every complaint
  • staff can view and update status (PENDING, IN_PROGRESS, RESOLVED)
  • use a mutex so two clients dont write the file together

Architecture

User client  --\
                 TCP --> C Server (one thread per client + mutex) --> complaints file
Staff client --/

Server steps: socket() → bind() → listen() → accept() → pthread_create() → recv() / send()
